# 发射类任务：足球射门与篮球投篮

**日期：2026-09-28**
**范围：`ROADMAP` M3 的第四、第五项运动**

羽毛球发球（[`BADMINTON.md`](BADMINTON.md)）确立了"发射类"任务的形状：物体从机器人这一侧出发（被放下、
静止或滚动），被击出一次，飞向一个目标。足球射门和篮球投篮是同一个形状，共用 `rules/launch.py` 的
`LaunchJudge`、`scripts/generate_launch_banks.py` 生成器和 `scripts/run_fixture_baselines.py` 基线脚本。

| 任务 | Gymnasium ID | 固定集 | Judge |
|---|---|---|---|
| `football-kick-v0` | `MultiSportRobot/FootballKick-v0` | `football/kick-v0` | `FootballKickJudge` |
| `basketball-shoot-v0` | `MultiSportRobot/BasketballShoot-v0` | `basketball/shoot-v0` | `BasketballShootJudge` |

动作/观测与其他夹具任务相同（7 维位姿、16 维观测），报告 schema、L0–L5 主指标名与门槛都相同。

---

## 一、任务坐标系放在目标处

所有任务的约定是：机器人在 x<0 一侧、朝 +x 出手。回球任务的原点在球台/球场中心；发射类任务把原点放在
**目标下方**：

- 足球：东侧**球门线中点**的地面，机器人在 x∈[−30, −8] 起脚；
- 篮球：东侧**篮圈圆心正下方**的地板，篮圈在 (0, 0, 3.05)，篮板前沿在 x=+0.34。

MuJoCo 场景仍按国际比赛尺寸建在世界原点，`MujocoSportProfile.task_origin` 声明平移，后端在边界处换算：
发射状态、球状态、接触点、观测、动作全部是任务坐标，Judge 从不见到场景坐标。网球/乒乓球/羽毛球的原点
不变（恒等变换）。

## 二、规则

**足球（IFAB 第 10 条）**：**整个球**越过球门线、且在两门柱之间、横梁之下才算进球——Judge 等球心越过
门线一个球半径时判定，此时 |y|<3.66 m 且 z<2.44 m 为进球，否则为 `out`（偏出/高出）。击中门框记入
`net_touch`，之后仍可能弹进。放置精度在**球门口平面 (y, z)** 上测量。

顺手修正了场景：原来的门柱中心放在 y=±3.66 m，内沿只有 7.20 m；横梁下沿 2.38 m。现在内沿 7.32 m、
横梁下沿 2.44 m（MuJoCo 与 Isaac 场景一致），球网后移 0.30 m，让球能完整越线后再被网兜住。

**篮球（FIBA 第 16 条）**：球从**上方**进入篮筐——Judge 判定球心向下穿过篮圈平面（z=3.05 m）时位于圈内
（内半径 0.225 m）。擦筐、打板都允许；从下方穿过篮圈判 `fault`。放置精度在**篮圈平面 (x, y)** 上测量，
L3 目标是"空心居中"和前/后偏移入筐。

## 三、物理：两处必须改的地方

### 1. 滚动的足球必须从"纯滚动"开始

固定集最初只给滚动球设线速度。这样的球其实是在**滑动**，地面摩擦在 0.3 s 内吃掉约 30% 的速度（实测横向
3 m/s → 2.13 m/s），"滚向你的球"其实是一颗急刹的球，脚本夹具因此几乎全部擦脚而过。现在生成器按
ω = (−v_y/r, v_x/r, 0) 给地面上的运动球设角速度（0.3 s 后 2.97 m/s），manifest 如实声明对应的 spin 范围。

### 2. 足球场景用 PGS 求解器

鞋面击打静止在地面上的球时，同一步里球同时受两个软接触（地面、鞋面）。MuJoCo 默认的 Newton 求解器对这对
接触的解不唯一：沿世界 x 轴踢球时一切正常（方向误差 0.2°），沿对角或 y 轴踢时，它返回了**互相抵消的
千牛级法向力与摩擦力**，球偏离鞋面法向 4–7° 并带 20–30 rad/s 的伪旋转——只与世界坐标方向有关，纯属数值
伪影。改拍面摩擦、接触维度、迭代次数、noslip、impratio 都无效；**PGS 求解器在所有方向上误差 0.15°、无旋转**。
只对足球 benchmark 场景启用（`scene.BENCHMARK_SOLVERS`），规则落球测试不受影响。

## 四、脚本夹具与接触模型

两个夹具（`launch_controllers.py`）实测同一个接触律：拍面沿其法向给球冲量，

    v_out = v_in + 1.21 · (u − v_in·n) · n

（足球鞋面对静止球：出球/鞋速比恒为 1.21；篮球推板对下落球同样成立）。控制器反解：给定想要的出球速度，
面法向 n ∥ (v_out − v_in)，面速 u = |v_out − v_in|/1.21 + v_in·n。想要的出球速度用后端同款阻力模型积分求出
（`BallFlightModel.fly_until`）：射门按目标高度二分仰角，投篮按随距离变陡的出手角（2 m 时 65°、6 m 以外 52°）
二分出手速度。

篮球还有一个实测修正：推板推球约 10 ms，球在**分离时刻**才以计划速度离开，此时已沿法向前移约 v·τ。
按"在接触点瞬间出手"规划，每个投篮都偏长 10–15 cm、砸在篮筐后沿；把出手点建模为接触点 + v·τ 之后，
入筐点距圈心 ≤7 cm。足球不需要这个修正（按接触点规划即在 1 cm 以内）。

## 五、固定集

由 `scripts/generate_launch_banks.py --sport football|basketball` 生成，每级 train 200 / dev 50 / test 100。

| 级别 | 足球 | 篮球 |
|---|---|---|
| L0 | 禁区内静止球，无动作；1 s 后仍静止在场内 | 罚球线附近放手，无动作；落在篮筐前方 |
| L1 | 禁区内静止球 | 罚球线附近放手 |
| L2 | 禁区及弧顶附近静止球（x∈[−22,−11]，\|y\|≤12） | 中距离 2.5–5.5 m |
| L3 | L2 + 四个角目标（上/下 × 左/右，半径 0.5 m） | L2 + 空心居中 / 前 / 后入筐目标 |
| L4 | 远射、大角度、回滚球、横滚球 | 三分、底角、低出手、上抛球 |
| L5 | 留出组合 + 观测噪声、延迟、域随机化 | 同左 |

## 六、实测基线

test split（每级 100）。完整表见 [`reports/football-baselines.md`](../reports/football-baselines.md)、
[`reports/basketball-baselines.md`](../reports/basketball-baselines.md)，全部任务汇总见
[`reports/cross-task-summary.md`](../reports/cross-task-summary.md)。

| Level | 足球 `scripted` | 篮球 `scripted` | 门槛 |
|---|---|---|---|
| L0 | 100% PASS（不动） | 100% PASS（不动） | 100% |
| L1 | 100% PASS | 100% PASS | 90% |
| L2 | 100% PASS | 100% PASS | 80% |
| L3 | **100% PASS** | 65% | 70% |
| L4 | **100% PASS** | 36%（最弱：`tossed`；总体 84%） | 60% |
| L5 | 18%（总体 26%） | 12%（总体 13%） | 50% |

`noop` 在两项任务上除 L0 外全为 0。

读法：

- **足球**：读精确状态、按阻力模型反解的夹具在无扰动时几乎完美——任务本身可解、判定链路正确。
- **篮球**：L3（目标半径 5–6 cm）与上抛球（L4 `tossed`）是夹具的短板：球在上升时被推板击出，实测出手
  竖直速度比冲量模型低约 0.1 m/s，偏差不是单纯的接触期重力（补偿它会让其他投篮全部偏长），没有继续精调。
- **L5 两项都很低**：夹具只在第一帧规划一次，不滤波、不感知延迟。0.3 m/s 的速度噪声在足球 0.3 s 的
  预测窗口里是 9 cm 的接触点误差，15 ms 的总延迟让篮球的出手点偏几厘米——对 ±10 cm 容差的篮圈足以致命。
  这正是 L5 要测的东西。
