# 学习基线（M5 第一批）

**日期：2026-09-28**

在此之前，本项目所有基线都是脚本控制器，而且大多读特权状态、用了对仿真器的标定知识（射程表、冲量增益、
阻力模型）。它们刻画的是"夹具能做到什么"，不是"策略能学到什么"。这一批是第一组**从交互中学出来**的基线。

## 一、问题设定：在一个挥拍原语上学参数

直接在 200 Hz 的 7 维位姿动作上做强化学习，面对的是稀疏的"进/不进"奖励和几秒长的回合；在本机的 CPU 预算下
不会有可读的结果。所以这一批学的是**一个动作原语的参数**：

| 任务族 | 原语 | 策略输出的 3 个参数 | 策略看到的特征 |
|---|---|---|---|
| 发射类（羽毛球/足球/篮球） | `SwingPrimitive`：预测接触点，拍面沿法向直线穿过它 | 面速、仰角、相对瞄准方向的偏航修正 | 接触点到瞄准点的水平距离、接触高度、接触时球速、瞄准高度、目标有无与半径 |
| 回球类（乒乓球/网球） | `ReturnPrimitive`：参考夹具的挥拍动作 | 挥拍速度、拍面仰角、开始挥拍的位置 | 来球初始位置/速度/角速度、目标中心与半径 |

原语只用**观测几何**：观测到的球状态外推到接触时刻、瞄准点（有 L3 目标时就是目标——目标是任务信息，见
[`POLICY_INTERFACE.md`](POLICY_INTERFACE.md)）。原语里**没有任何对仿真器的标定**：不知道出球/拍速比、
不知道射程、不知道阻力。这些正是策略要学的。

每个回合只做一次决策（`PrimitiveLaunchEnv`：一步一回合的 Gymnasium 环境，一步 = 一整个真实 MuJoCo 回合、
由真实 Judge 判定），用 PPO（Stable-Baselines3，MLP 64×64，`gamma=0`）训练。奖励：

    0.1·hit + valid_return + target_hit + 0.5·exp(-(target_error/radius)²)（仅在成功时）

## 二、协议

- **train split 训练、test split 评测**，种子由固定集生成器保证不重叠；
- **5 个训练种子**，每个 8000 回合；报告逐种子结果与跨种子均值的 95% 区间（t 分布）；
- 评测走与其他基线**完全相同**的报告路径（`run_from_args`，同样的 L5 扰动、回合种子派生、Judge）；
- 同时报告 **random-primitive**：同一原语、参数均匀随机——学习策略必须超过它才有意义；
- 权重（`baselines/learned/<sport>/seed<N>.zip`）、训练曲线、超参数、墙钟时间与硬件（`seed<N>.json`）全部提交。

复现：

```bash
uv sync --extra test --extra train
PYTHONPATH=src python scripts/train_launch_policies.py --sport football    # 或 badminton / basketball / tennis / table_tennis
multisport-benchmark --sport football --level L3 --split test \
    --learned-policy baselines/learned/football/seed0.zip
```

## 三、结果

test split，5 个种子均值（括号里是**未训练原语** / **随机原语**）。每项任务的逐种子结果、95% 区间与训练曲线
见 `reports/learned-<sport>-baselines.md`，与所有其他基线的并列表见
[`reports/cross-task-summary.md`](../reports/cross-task-summary.md)。

| 任务 | L2 成功率 | L3 定点 | L4 最弱桶 | L5 最弱桶 |
|---|---|---|---|---|
| 乒乓球（夹具，`return-v1`） | **98%**（0% / 13%） | **25%**（0% / 4%） | **87%**（0% / 7%） | **42%**（14% / 9%） |
| 网球 | 60%（58% / 22%） | 2%（2% / 0%） | 21%（22% / 5%） | 0%（0% / 0%） |
| 羽毛球发球 | 100%（100% / 62%） | **36%**（19% / 8%） | 100%（100% / 36%） | 80%（79% / 36%） |
| 足球射门 | 100%（100% / 78%） | **9%（49%** / 9%） | 100%（100% / 56%） | 27%（21% / 15%） |
| 篮球投篮 | **36%**（2% / 4%） | **9%**（0% / 2%） | 2%（4% / 0%） | 7%（0% / 0%） |

"未训练原语"是三个参数都取区间中值——也就是 PPO 在任何学习之前的确定性动作。它是读这张表的关键对照：

- **乒乓球与篮球是真正学出来的。** 中值参数在这两项上几乎一无所获（乒乓球 L2 0%、篮球 L2 2%），训练后分别
  到 98% 与 36%。乒乓球的 L3/L4/L5 也都远高于两个对照。
- **羽毛球的定点是学出来的**（L3 19% → 36%）；合法发球本身中值参数就能做到。
- **网球没有学到东西。** 中值参数（15 m/s、15°、在 x=−5.5 m 起拍）恰好接近人工调好的夹具默认值
  （14 m/s、14°、−5 m），学习后的成绩与它持平（L2 60% vs 58%），训练曲线也基本是平的。
- **足球的定点被训练弄坏了**（L3 49% → 9%）。进球率一直是 100%，但 PPO 优化的是**带着自身探索噪声**时的
  期望奖励：在宽的高斯噪声下，"更稳地进球"比"瞄准角落"期望更高，于是它收敛到一个牺牲落点的均值动作，
  确定性评测时就把中值原本具备的定点能力丢掉了。这说明这套协议下的 PPO 并不适合精细定点；更小的初始方差、
  更多 L3 样本或按级别分开训练都可能改善，但本批次没有做——**不为让表格好看而逐任务调参**。

与参考控制器相比：乒乓球夹具的学习策略在 `return-v1` 上的 L2（98%）远高于 Panda 机体上的 `intercept`（16%），
但**两者不可比**——夹具的拍面每个控制步可以瞬移到任何位姿，机械臂受关节速度与可达性约束，Panda 的瓶颈
正是回球所需的拍速（见 `ROBOT_LAYER.md`）。篮球的学习策略（L2 36%）远不如按阻力模型与冲量律反解的脚本夹具
（100%）——后者用了学习策略没有的标定知识。

## 四、这批基线不是什么

- **不是可提交成绩**：原语本身是人设计的结构，学的只是它的三个参数；
- **不是闭环策略**：一次决策、之后开环执行；L5 的观测延迟与噪声因此只影响那一次决策；
- **不是机体策略**：全部在 mocap 夹具上，机体（Panda/G1）上的学习基线仍缺；
- 训练量受本机 CPU 限制（与其他训练任务共享），更多回合可能继续提高 L3。
